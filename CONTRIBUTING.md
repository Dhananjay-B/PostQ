# 🤝 Contributing to PostQ

Thank you for your interest in contributing to PostQ.

Contributions of all sizes are welcome.

---

## 🚀 Getting Started

### 1. Fork the Repository

Click the **Fork** button on GitHub to create your own copy.

### 2. Clone Your Fork

```bash
git clone https://github.com/<your-username>/postq.git
cd postq
```
### 3. Create a Branch

``` bash
git checkout -b feature/short-description
```
Use clear branch names such as:

- feature/tls-enumeration-improvement
- fix/handshake-timeout
- docs/readme-update

## 📌 Contribution Rules

1. Only open Pull Requests for existing listed issues.
2. If no issue exists, open one first and discuss the proposal.
3. Contributors are encouraged to open new issues for:
   - Feature proposals
   - Bug reports
   - Enhancements
   - Performance improvements
   - Security improvements

Please wait for issue discussion/approval before submitting large changes.

## 🔁 Submitting a Pull Request

Before opening a PR:
- Ensure the project builds successfully.
- Keep changes focused and minimal.
- Clearly explain:
  - What changed
  - Why it changed
  - Any security implications

## 🔐 Security Contributions

If you discover a vulnerability or security improvement:
- Open an issue describing the concern (avoid disclosing sensitive exploit details publicly).
- Wait for discussion/acknowledgment. You must show exploit during discussion 
- Submit a patch following the standard contribution process.

Security patches are highly appreciated.
